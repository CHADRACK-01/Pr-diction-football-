# Prédiction Football

Application Python de pronostics sportifs combinant un bot Telegram, des modèles prédictifs et une interface Flask.

## Fonctionnalités

1. Alertes live : messages dès qu’un but tombe et contrôle du pari concerné.
2. Détecteur de value bet : compare la probabilité IA à la cote du bookmaker.
3. Tracker de chute de cotes : alerte lorsqu’une cote baisse rapidement.
4. Alerte composition officielle et absents : vérification avant le match et recalcul du prono.
5. Simulateur de cash-out : estime le gain selon la mise et la cote actuelle.
6. Mode Lingala et français : changement de langue avec la commande `/langue`.

8. Filtre anti-piège : badge rouge pour les matchs dangereux, notamment les derbies.
9. Pronostics corners et cartons : marchés spécialisés en plus du 1N2.

## Commandes locales ajoutées

- `/daily` : récupérer le bonus de connexion quotidien.
- `/roue` : utiliser la roue quotidienne gratuite.
- `/xp` : consulter le solde XP.
- `/montecarlo LAMBDA_DOMICILE LAMBDA_EXTERIEUR SIMULATIONS` : lancer une simulation.
- `/derby EQUIPE1 vs EQUIPE2` : détecter une rivalité connue.
- `/elo ELO_DOMICILE ELO_EXTERIEUR BUTS_DOMICILE BUTS_EXTERIEUR home|away` : recalcul Elo après un but.
- `/fatigue DATE1 DATE2 DATE3` : analyser la densité du calendrier.
- `/antiperte P P P` : appliquer la règle anti-perte.
- `/cashpartiel MISE COTE_INITIALE COTE_ACTUELLE FRACTION` : simuler un cash-out partiel.

## État d'implémentation

Le catalogue complet compte jusqu’à 700 fonctionnalités. Certaines sont complètes, d’autres partielles ou à compléter.

- `complete` : disponible dans le code et raccordé aux services existants.
- `partielle` : module présent, mais automatisation ou interface complète encore manquante.
- `a_implanter` : fonctionnalité prévue mais sans implémentation utilisable vérifiée.

Le catalogue technique centralisé se trouve dans `core/catalogue_fonctionnalites.py`. Les statuts doivent être maintenus avec les tests associés avant toute livraison.

## Configuration

L'application exige les variables d'environnement suivantes :

| Variable | Description |
|---|---|
| `TELEGRAM_TOKEN` | Jeton du bot Telegram |
| `TELEGRAM_WEBHOOK_SECRET` | Secret du webhook Telegram |
| `ADMIN_ID` | Identifiant Telegram de l'administrateur |
| `CANAL_ID` | Identifiant ou username du canal |
| `TURSO_URL` | URL de la base Turso |
| `TURSO_TOKEN` | Jeton d'accès Turso |

Variables optionnelles :

- `FOOTBALL_DATA_KEY`
- `BZZOIRO_API_KEY`
- `API_FOOTBALL_KEY_1`
- `API_FOOTBALL_KEY_2`
- `AIRTEL_API_KEY` + `AIRTEL_API_URL`
- `ORANGE_API_KEY` + `ORANGE_API_URL`
- `MPESA_API_KEY` + `MPESA_API_URL`
- `CANAL_USERNAME`
- `CANAL_LIEN`
- `MODE_TEST` (`true` ou `false`)
- `MODE_VITRINE` (`true` ou `false`)
- `RENDER` (`true` pour utiliser le dossier `/tmp/data`)

## Structure principale

- `app.py` : application Flask, bot Telegram et tâches planifiées
- `config.py` : configuration et validation des variables d'environnement
- `core/` : prédictions, statistiques, paiements, alertes et services métier
- `telegram_bot/` : commandes et gestionnaires Telegram
- `users/` : utilisateurs, abonnements et accès à la base de données
- `entrainement/` : entraînement des modèles
- `scripts/` : téléchargement des matchs et mise à jour des résultats
- `tests/` : tests unitaires et d'intégration

## Base pour les compléments externes

Les intégrations nécessitant des comptes, des clés API ou des autorisations ne doivent pas être considérées comme fonctionnelles tant que les fournisseurs ne sont pas configurés.

Une base structurée est disponible dans :

- `core/socles_tiers.py` : paiements, réseaux sociaux, audio et calendrier
- `core/sauvegarde_backup.py` : export, manifest et sérialisation des sauvegardes
- `docs/01_base_interventions_humaines.md` : informations, secrets et décisions à fournir par l’administrateur

Les adaptateurs tiers indisponibles retournent explicitement une erreur et n’attribuent jamais un paiement, une publication ou un succès fictif.
